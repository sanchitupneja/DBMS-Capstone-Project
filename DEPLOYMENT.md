# Deploying to Render (MongoDB version)

The live application uses **MongoDB** (Prisma ORM 6.19 — Prisma 7 does not yet
support MongoDB). The original MySQL/MariaDB files are preserved in
`sql-reference/` as syllabus material and are not used at runtime.

The Blueprint creates two services:

| Service | Purpose |
| --- | --- |
| `hostel-allocation-api` | Express API (Docker) |
| `hostel-allocation-frontend` | Next.js UI |

## 1. Create a MongoDB Atlas cluster (free)

1. Sign up at [MongoDB Atlas](https://www.mongodb.com/atlas) and create a
   **free M0 shared cluster** (a replica set is required because Prisma uses
   transactions internally).
2. Create a database user (`Database Access → Add New Database User`) with a
   password, and allow access from anywhere (`Network Access → Add IP Address →
   0.0.0.0/0`) so Render can connect.
3. `Connect → Drivers → Node.js`, and copy the connection string. It must end
   with the database name, e.g.:
   ```
   mongodb+srv://USER:PASSWORD@cluster.mongodb.net/hostel_allocation_db?retryWrites=true&w=majority
   ```
   Percent-encode special characters in the password.

## 2. Push the code to GitHub

The repo has an initial commit but no remote yet:

```bash
git remote add origin https://github.com/<YOUR_USER>/<YOUR_REPO>.git
git branch -M main
git push -u origin main
```

## 3. Create the Blueprint

1. Render Dashboard → **New → Blueprint** → connect the repo → branch `main`.
2. When prompted for `DATABASE_URL`, paste the Atlas connection string from
   step 1. JWT secrets are generated by Render.
3. Click **Apply** and wait for both services to be Live (first build takes a
   few minutes).

On startup the API container runs `npx prisma db push`, which creates the
collections and unique indexes. On the first successful deploy Render also runs
`npm run db:seed`, which loads demo data:

## 4. Verify

- API health: `https://hostel-allocation-api.onrender.com/api/health`
- Frontend: `https://hostel-allocation-frontend.onrender.com`

## 5. Local development

```bash
npm install
# put your Atlas URI in .env as DATABASE_URL
npx prisma db push
npm run db:seed
npm run dev:all
```

Prisma Studio: `npm run db:studio`.

Useful scripts: `npm run db:generate`, `npm run db:push`, `npm run db:reset`
(`db push --force-reset` — destructive), `npm run db:seed:allocations`.

## 6. Notes

- **Free tier**: both Render web services spin down after inactivity; the first
  request after a pause can take ~30–60 seconds. Atlas M0 is free but has
  cluster/storage limits.
- **CORS**: the API accepts an explicit `CORS_ORIGIN` list (comma-separated)
  plus any `*.onrender.com` origin in production. Set `CORS_ORIGIN` to your exact
  frontend URL for stricter security.
- **Frontend API URL**: `NEXT_PUBLIC_API_URL` is baked in at build time. If you
  change the API service URL, redeploy the frontend.
- **MongoDB specifics**: no Prisma Migrate (indexes are managed with `db push`),
  IDs are `ObjectId`, relations use stored ID references instead of SQL foreign
  keys, and transactions require the Atlas replica set.
- **SQL reference**: relational equivalents (DDL, sample data, report queries
  with joins and grouping) remain in `sql-reference/` for comparison.
