# Deploying to Render

This repository is prepared for Render's **Blueprint** deployment. One blueprint
creates three services:

| Service | Type | Purpose |
| --- | --- | --- |
| `hostel-allocation-db` | Private service (`mariadb:11`) + 5 GB disk | Database |
| `hostel-allocation-api` | Docker web service | Express API |
| `hostel-allocation-frontend` | Node web service | Next.js UI |

Secrets (DB passwords, JWT keys) are generated by Render — nothing needs to be
typed into the blueprint form.

## 1. Push the code to GitHub

The repository has an initial commit but no remote yet. Create a GitHub repo,
then run:

```bash
git remote add origin https://github.com/<YOUR_USER>/<YOUR_REPO>.git
git branch -M main
git push -u origin main
```

## 2. Create the Blueprint

1. Log in to [Render Dashboard](https://dashboard.render.com).
2. Click **New → Blueprint**.
3. Connect the GitHub repo you just pushed.
4. Render detects `render.yaml` at the repo root. Use branch `main`.
5. Click **Apply**.

Render will create the MariaDB service first, then the API and frontend. Wait for
all three to reach a **Live** state (the first build takes several minutes).

## 3. Verify the deployment

- API health: `https://hostel-allocation-api.onrender.com/api/health`
- Frontend: `https://hostel-allocation-frontend.onrender.com`

The exact URLs are shown on each service page in Render. On the first successful
API deploy, Render runs `npm run db:seed`, which loads demo data:

## 4. What was configured for deployment

- **Docker build**: `prisma generate` uses a placeholder `DATABASE_URL` during the
  image build (the Prisma client uses a runtime adapter, so no real DB is needed).
- **Migrations**: `docker-entrypoint.sh` builds `DATABASE_URL` from the `DB_*`
  variables wired from the MariaDB service, runs `prisma migrate deploy`, then
  starts the API. This works on the free plan too.
- **CORS**: the API accepts an explicit `CORS_ORIGIN` list (comma-separated) plus
  any `*.onrender.com` origin in production, so the frontend works out of the box.
  For stricter security, set `CORS_ORIGIN` on the API service to your exact
  frontend URL and redeploy.
- **Frontend API URL**: the build command composes `NEXT_PUBLIC_API_URL` from the
  API service's public Render URL.
- **Seeding**: `initialDeployHook` runs once after the first deploy. To reseed
  later, open the API service's Shell tab in Render and run `npm run db:seed`.

## 5. Important notes

- **Costs**: the private MariaDB service uses a paid `0.5c-512mb` plan plus a 5 GB
  disk. The API and frontend use the free plan. Free web services spin down after
  inactivity, so the first request after a pause can take ~30–60 seconds.
- **Disk = your database**: do not reset/delete the `hostel-mariadb-data` disk.
  Back up with `mysqldump` before destructive operations.
- **If the frontend shows API errors**: check the frontend service's `API_URL`
  env var and rebuild the frontend. `NEXT_PUBLIC_*` variables are baked in at
  build time, so changing one requires a redeploy.
- **If CORS errors appear in the browser console**: set `CORS_ORIGIN` on the API
  service to the exact frontend URL (comma-separated if you use several domains)
  and redeploy the API.
- **Environment changes**: Render preserves env vars you add in the dashboard
  even when the blueprint syncs again.
